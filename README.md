# RayVoxel

Небольшой рабочий прототип воксельной игры на Rust `1.97.1`, `wgpu 30` и WGSL.
Это не растеризация кубических мешей: каждый пиксель запускает луч, проходит
воксели DDA-алгоритмом и пересекает slab как AABB нужной высоты.

## Что реализовано

- Блок хранит материал и высоту верхней части в 1/16 блока. Обычный блок имеет
  высоту 16, а рельеф генерирует настоящие slab-высоты от 1 до 15.
- Вокруг игрока стримятся `9 × 9` детальных чанков `16 × 48 × 16`; лишние
  чанки выгружаются с сохранением короткого защитного кольца.
- Дальний слой сделан по архитектурному принципу Distant Horizons: разреженный
  quadtree из независимых `16 × 16` full-data-секций, с пятью уровнями
  объединения (`1×…16×`) и горизонтом радиусом `256` чанков. Секции ставятся в
  очередь по манхэттенскому расстоянию, строятся фоновым потоком и не тормозят
  ходьбу; готовый более грубый родитель остаётся видимым, пока дочерний уровень
  ещё загружается. Каждый столбец содержит высоту с точностью `1/16`, материал
  верха и отдельный материал обрыва, поэтому дальние холмы имеют траву,
  камень, грунт и воду, а не один зелёный heightmap. Кэш источников хранится
  между запусками в `cache\distant_horizons\v1` рядом с папкой игры и
  автоматически пересоздаётся при смене формата. Дальний рельеф участвует в
  солнечных тенях.
- Деревья хранятся и растут как sparse-наборы блоков, по модели Dynamic Trees:
  rooty soil с плодородием, root-to-tip `GrowSignal`, дискретные радиусы ветвей,
  возвратный расчёт площади дочерних ветвей, гидратация динамических листьев и
  cellular decay. Рендер — перенос публичного алгоритма Eco Machina Visualizer:
  BFS-иерархия древесины, веса поддеревьев, heavy-path chains, одна угловая
  прямоугольная spine-полоса на wood-block и отдельные коннекторы только для
  не-primary chains. Толщина каждой spine берётся напрямую из `Dynamic Trees`
  `branch radius` (`1..8` → half-width `1/16..8/16` блока); у коннектора
  используется меньший из двух связанных DT-радиусов. Лист сам выбирает wood
  соседа с приоритетом face/tip и получает alpha-тестируемый квадратный
  коннектор. В 3D восемь 2D-соседей визуализатора расширены до 26 ближайших
  клеток; топология древесины остаётся шестигранной Dynamic Trees. Никаких
  core/sleeve, конусов или запасного рендера ветвей нет.
- GPU-атлас материалов деревьев собирается при запуске из внешних PNG: кора и
  отдельный end grain с кольцами для трёх видов, листовые текстуры и шесть
  прозрачных вариантов twig-коннектора. Торец определяется в локальном базисе
  ветви, поэтому кольца корректны и у наклонной древесины. Атлас
  непосредственно участвует в трассировке лучей, включая alpha-тест спрайта.
- Исходные PNG не зашиты в бинарник: их список и размер плитки задаёт
  `assets/tree/tree_textures.json`; все пути в нём относительны к самому JSON.
  Игра читает их при запуске и немедленно завершится с понятной ошибкой при
  неверном размере, отсутствующем файле или потерянной alpha-маске.
- Солнце проходит 150-секундный цикл дня/ночи. Прямой солнечный свет делает
  вторичный трассировочный луч и даёт тени от блоков, slab и деревьев.

## Запуск

```powershell
cargo run --release
```

Управление: `WASD` — движение, стрелки — обзор, `Space`/`Shift` — вверх/вниз,
`Left Ctrl` — ускорение, `Esc` — выход. Заголовок окна показывает число
загруженных детальных чанков и активных Dynamic Trees.

## Профилирование

Обычный build не содержит профилирующего клиента и не запрашивает GPU timer
queries. Для профилирования используется отдельная локальная сборка:

```powershell
cargo run --release --features profiling
```

- CPU timeline записывается в [Tracy](https://github.com/wolfpld/tracy): main
  thread, stream чанков, Dynamic Trees, загрузка/генерация LOD-секций на
  worker-потоке, GPU uploads, encode/submit/present. Клиент ограничен
  `localhost`; Tracy viewer можно подключить до или после запуска игры.
- GPU timestamp queries измеряют `RayVoxel::Raytrace` без ожидания GPU: шесть
  readback-буферов возвращают результаты через несколько кадров. Среднее и p95
  видны в заголовке окна и как plot `GPU Raytrace (ms)` в Tracy.
- GPU capture tools получают маркеры `RayVoxel::Frame` и
  `RayVoxel::Raytrace`. Используй PIX или Nsight Graphics для source-level
  анализа монолитного WGSL ray pass: portable `wgpu` timestamps честно
  измеряют GPU-проход, но не могут приписать время отдельным функциям внутри
  одного fragment shader.
